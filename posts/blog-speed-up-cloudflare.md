# 国内访问 GitHub Pages 博客提速：Cloudflare 关代理直连实测

博客部署在 GitHub Pages，域名在 Cloudflare 托管。前几天有朋友反馈：**不挂梯子国内基本访问不进去**。排查下来，问题出在一个很多人都会踩的配置上。

## 症状

- 国内直连 `https://xkbk.cn`：大部分时候超时，偶尔能开也是 8-10 秒
- 挂梯子：秒开

## 排查：定位到 Cloudflare 代理

先用 `nslookup`/`dig` 看域名解析到了哪：

```
xkbk.cn → 104.21.35.100
xkbk.cn → 172.67.217.72
```

这两个 IP 是 **Cloudflare 的代理节点**。说明域名开了 CF 的"橙色云朵"（代理模式）。

问题就在这：**Cloudflare 免费版没有中国大陆节点**，大陆用户访问时请求要绕到 CF 的海外节点（日本、美国、欧洲），延迟极高且经常被干扰——这是所有 CF 免费用户的通病。

而 GitHub Pages 自己的 IP（`185.199.108.153` 等四个）虽然不算快，但在国内大部分地区**直连是通的**（时好时坏，但比 CF 代理强得多）。

## 解决方案：关代理，仅 DNS

### 第一步：Cloudflare 关闭代理

进入 Cloudflare → DNS 管理，把 `xkbk.cn` 的记录从「已代理」（橙色云朵）改为「**仅 DNS**」（灰色云朵）。

### 第二步：删掉"僵尸记录"

这里有个隐藏坑：域名之前开过代理，Cloudflare 会在记录里留下两条指向 CF 节点的 A 记录（`104.21.35.100`、`172.67.217.72`）。**关掉代理后这两条必须删掉**——它们指向的 IP 上没有任何服务（CF 代理 IP 只响应开启了代理的域名），不删的话解析有一半概率落到它们身上，直接超时。

删完后只剩 GitHub Pages 的 4 条 A 记录：

```
185.199.108.153
185.199.109.153
185.199.110.153
185.199.111.153
```

### 第三步：等待生效并实测

DNS 生效 5-10 分钟，然后用**手机流量**（关 wifi、关梯子）实测：

| 阶段 | 访问耗时 |
|---|---|
| CF 代理模式 | 8-10 秒 / 超时 |
| 关代理直连后 | **1.7-3 秒，稳定 200** |

提速效果非常明显。

## 踩坑总结

1. **CF 免费版代理 = 国内访问减速器**，托管 DNS 可以，但别开"橙色云朵"
2. 关代理后记得清理旧记录：CF 代理 IP 的 A 记录就是"僵尸记录"，留着会随机拖慢一半请求
3. GitHub Pages 直连国内"能用但不完美"——部分地区仍可能慢。想更稳可以迁 Vercel（自定义域名，有香港节点），实测国内 3 秒级

## 进阶备选：Vercel

如果关代理后仍觉得不稳，把博客迁到 Vercel（免费、自动构建、支持 GitHub 仓库导入），域名 CNAME 到 `cname.vercel-dns.com` 并保持"仅 DNS"，国内访问通常比 GitHub Pages 直连更稳定——你的 Twikoo 评论后端已经在 Vercel 上跑得好好的，博客迁过去速度和它一样。

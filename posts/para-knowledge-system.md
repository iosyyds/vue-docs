# 个人知识库 PARA 体系：文件不再乱成堆

打开笔记软件，左边是一长串文件夹：技术、生活、工作、收藏、待整理、旧资料……每一层里面还有七八个子目录。想找一篇三个月前存的配置教程，搜关键词翻了十分钟，最后还是重新 Google 了一遍。

问题不在工具，在结构。PARA 是 Tiago Forte 提出的一套通用文件组织方法，核心只有四个字母，却能把「收藏」和「使用」分开。

![PARA 四层结构总览](/images/tutorial/para-system-1.svg)

## 一、四个目录的分工

PARA 把一切资料分成四类：

- **Projects（项目）**：有明确目标、有截止时间的短期任务。比如「博客迁移」「四级备考」「暑期实习报告」。
- **Areas（领域）**：需要长期维护、没有终点的责任范围。比如「健康」「财务」「职业发展」「家庭」。
- **Resources（资源）**：有兴趣但没有直接行动关系的资料。比如「设计参考」「开源工具」「读书笔记」。
- **Archives（归档）**：已完成或不再活跃的内容，从上面三类里挪过来。

判断标准很简单：**这件事有截止时间吗？有就是 Project；没有但需要长期负责就是 Area；跟具体行动无关就是 Resource**。

## 二、目录落地

在笔记软件里建四个顶层目录，编号保持固定顺序：

```
00-项目/
  ├── 博客迁移复盘/
  ├── 四级冲刺/
  └── 实习报告撰写/

01-领域/
  ├── 健康管理/
  ├── 财务记账/
  └── 职业发展/

02-资源/
  ├── 技术资料/
  ├── 设计参考/
  └── 工具清单/

03-归档/
  └── 2025/
```

编号只是为了让排序稳定，Obsidian、Notion、本地文件夹都适用。不要在里面再套太多层级，**三层以内能解决 95% 的问题**。

## 三、每条资料的归属判断

存一条新资料时问三个问题：

1. 它服务于当前正在做的某个具体任务吗？→ 放进对应 Project
2. 我需要在未来长期维护相关的能力或责任吗？→ 放进对应 Area
3. 只是以后可能用到？→ Resources，但必须打标签

第 3 条最关键。Resources 是最容易堆垃圾的地方，所以给每条资料加两个标签：**主题标签**（如 `#nginx`）和**行动标签**（如 `#待实践`）。

只有带 `#待实践` 的资料才会在每周复盘时被翻出来，其余就是纯检索库，不占注意力。

![资料归类的三个判断问题](/images/tutorial/para-system-2.svg)

## 四、每周十分钟的维护习惯

PARA 不是建完就一劳永逸，需要每周清理一次：

- **Project 结束就归档**：完成的项目整个文件夹移到 `03-归档/年份/`，不要留在项目区干扰视线
- **清理 Resources 的僵尸条目**：三个月没被引用、也没有行动标签的资料，删掉或合并
- **Area 做一次体检**：每个领域写下当前最重要的一个问题，没有进展就说明该调整精力分配

建议在日历上固定一个「每周日 20:00 整理知识库」的日程，十分钟就够。

## 五、和博客写作结合

写博客时，素材基本都来自 Resources。成文过程是：

1. 在 Resources 里按主题标签聚合素材
2. 新建一个 Project（比如「写一篇 Nginx 反向代理教程」）
3. 成稿发布后，把素材链接挂到文章末尾的「参考资料」，Project 归档
4. 文章本身成为 Area（内容运营）里的产出记录

这样每篇文章都有来源、有归档、有复盘，不会出现「写了一堆但不知道写过什么」的情况。

## 小结

PARA 的价值不在四个文件夹，而在它强制你做一次判断：**这条资料到底服务于什么**。想不清楚的，就不该存。知识库的质量取决于删掉多少，而不是存了多少。

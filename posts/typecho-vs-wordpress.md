# Typecho 还是 WordPress：个人博客怎么选

想搭一个有后台的博客，绕不开这两个名字。搜索引擎里的对比文章大多停留在「Typecho 轻量、WordPress 强大」这种正确但没用的结论上。

这篇按实际使用场景拆开讲：**你会在什么情况下感到区别**。

![Typecho 与 WordPress 的定位对比](/images/tutorial/typecho-wp-1.svg)

## 一、资源占用：小机器上的差距很明显

Typecho 的核心代码不到 1 MB，典型页面查询几条 SQL，1 核 512 MB 的机器就能跑得很稳。

WordPress 装上主题和几个插件后，单次请求可能查询几十条 SQL，内存占用轻松到 200 MB 以上。1 核 1 GB 是底线，插件多了 2 GB 才稳。

**实际感受**：Typecho 在 2 核 2G 的机器上打开文章页约 50~100 ms；WordPress 同等配置加缓存插件约 150~300 ms。都够用，但低配机器上差别明显。

## 二、后台体验：写文章的感受

**Typecho**：

- 编辑器是简洁的 Markdown/HTML 编辑框，没有花哨的区块
- 发布流程三步：写、选分类标签、发布
- 附件管理简单，图片插入靠 Markdown 语法

**WordPress**：

- 区块编辑器（Gutenberg）所见即所得，排版直观
- 媒体库管理成熟，图片自动生成多种尺寸
- 但后台加载慢，插件多了菜单层级复杂

如果你习惯 Markdown，Typecho 更顺手；如果习惯可视化排版，WordPress 更友好。

## 三、扩展性：插件生态的差距

WordPress 有上万个插件：SEO、缓存、表单、电商、会员、多语言，几乎任何需求都有现成方案（质量参差）。

Typecho 的插件生态小得多，但常用的都有：Markdown 解析、评论审核、SEO、备份、图片灯箱。

**关键判断**：如果你的需求是「标准博客」——文章、分类、标签、评论、RSS——两者都够。如果你要做「带会员、付费、电商、多作者」的站点，WordPress 的生态优势无法替代。

![扩展需求与程序匹配度](/images/tutorial/typecho-wp-2.svg)

## 四、维护成本：安全更新的现实

WordPress 是攻击者重点目标，核心、主题、插件都需要持续更新。不更新的站点，几个月后可能被挂马。维护成本是长期的。

Typecho 用户基数小，自动化攻击相对少，但也不是没有漏洞。更新频率低（几年一个大版本），维护压力小。

**注意**：无论哪个，都要做到：

- 后台强密码 + 两步验证
- 定期备份数据库和上传目录
- 关闭不用的插件/主题
- 不装来源不明的破解主题

## 五、迁移难度

两个程序都支持从 Markdown 或 RSS 导入。Typecho 的文章表结构简单，导出成 Markdown 很容易；WordPress 有官方导出工具（XML），但附件和短代码迁移经常出问题。

如果你现在用静态博客（VitePress/Hugo），迁到 Typecho 更简单：Markdown 原文直接进数据库，配一个 Markdown 插件即可。

## 六、我的建议

**选 Typecho，如果**：

- 个人博客，文章为主
- 服务器配置不高（1~2 核）
- 喜欢 Markdown 写作
- 不想每周折腾插件更新

**选 WordPress，如果**：

- 需要成熟的主题市场和可视化编辑
- 要做会员、付费内容、多作者
- 有运维经验，能hold住插件和安全更新
- 未来可能扩展成内容站/小型电商

## 七、还有第三条路

如果博客主要是静态内容，其实不必上动态程序：VitePress、Hugo 这类静态生成器 + GitHub Pages/Cloudflare Pages，成本几乎为零、速度极快、安全性最好。

动态程序的价值在于**后台管理**和**评论/搜索等交互**。如果你需要的只是「在网页上写文章」，静态博客配合在线编辑器也能做到。

程序只是工具，先想清楚你要的是「写文章的地方」还是「运营一个站点」，答案会清楚很多。
